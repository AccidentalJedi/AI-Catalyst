OverviewOllama is a powerful tool for running large language models (LLMs) locally, and it provides a range of adjustable options to tailor its performance to your needs. Here's a breakdown of how you can customize it, especially for using the LLM server, and what automated features it offers for GPU and system assessment.Adjustable OptionsYou can tweak Ollama through a Modelfile, which lets you set parameters like context window size, temperature for creativity, and max tokens to predict. Environment variables also allow you to configure server settings, such as where models are stored or how long they stay in memory. These options give you flexibility to match your hardware and use case.Automated FeaturesOllama seems to automatically detect and use available GPUs, and it adjusts some settings, like the number of concurrent models, based on your system's memory and GPU count. This helps optimize performance without manual tweaking, though some settings still require manual configuration.Context and Max Token SettingsYou can set the context size (CTX) and max tokens manually, either in the Modelfile or via environment variables. While Ollama doesn't fully automate these, it provides defaults that work well for most systems, and some parameters auto-adjust based on resources.Model LayersIt appears you can influence model layers through adapters (like LoRA) in the Modelfile and quantization settings via environment variables, but automation for this is less clear and may require manual setup.For more details, check out the official documentation: Ollama Modelfile Documentation, Ollama FAQ.Comprehensive Survey NoteThis survey note provides an in-depth exploration of all adjustable options and features related to the Ollama LLM server as of July 2025, focusing on its capabilities for customization, automated features for GPU and system assessment, and specific settings for context (CTX), max tokens, and model layers. The information is derived from official documentation, community discussions, and recent updates, ensuring a thorough understanding for users looking to leverage Ollama for local LLM deployment.Introduction to Ollama and Its ServerOllama is a cross-platform inference framework designed for seamless deployment of large language models (LLMs) such as Llama 3.1, Mistral, and others, enabling local execution with enhanced data privacy and security. It starts an API service on port 11434 by default, accessible at http://localhost:11434, and supports integration with various tools and platforms, including Jupyter notebooks and LangChain. The server can be configured to optimize performance based on hardware capabilities, making it suitable for both personal and enterprise use.Adjustable Options and FeaturesOllama offers extensive customization through two primary mechanisms: the Modelfile and environment variables. These allow users to fine-tune model behavior, server settings, and resource utilization.Modelfile ConfigurationsThe Modelfile serves as a blueprint for creating and customizing models within Ollama. It supports several instructions, each with adjustable parameters:PARAMETER Instructions:num_ctx: Sets the context window size, controlling how many tokens the LLM can use as context. Default is 2048, but can be set to higher values like 4096 for broader context understanding.
repeat_last_n: Determines how far back the model looks to prevent repetition, with a default of 64. Can be set to 0 (disabled) or -1 (equal to num_ctx).
repeat_penalty: Penalizes repetitions, with a default of 1.1. Higher values (e.g., 1.5) penalize more strongly, while lower values (e.g., 0.9) are more lenient.
temperature: Controls creativity, with a default of 0.8. Higher values increase creativity, lower values enhance coherence.
seed: Sets a random number seed for generation, defaulting to 0 for random output, but can be set to a specific value like 42 for reproducibility.
stop: Defines stop sequences to halt generation, allowing multiple sequences.
num_predict: Specifies the maximum tokens to predict, defaulting to -1 (infinite), but can be set to a specific number like 42.
top_k: Reduces nonsense by considering only the top k tokens, defaulting to 40, with higher values (e.g., 100) for diversity and lower (e.g., 10) for conservatism.
top_p: Controls diversity by considering the smallest set of tokens whose cumulative probability exceeds p, defaulting to 0.9, with higher values (e.g., 0.95) for diversity and lower (e.g., 0.5) for focus.
min_p: Sets the minimum probability for token consideration, defaulting to 0.0, but can be adjusted to values like 0.05 for stricter filtering.

TEMPLATE Instruction:Allows customization of the prompt template using Go template syntax, with variables like {{ .System }}, {{ .Prompt }}, and {{ .Response }}. This is useful for tailoring the interaction format, often using tags like <|im_start|> and <|im_end|>.

SYSTEM Instruction:Sets the system message to specify the behavior of the chat assistant, such as "You are Mario from Super Mario Bros, acting as an assistant."

ADAPTER Instruction:Specifies a fine-tuned LoRA adapter to apply to the base model, supporting models like Llama, Mistral, and Gemma. The adapter path can be absolute or relative, enabling customization without full retraining.

MESSAGE Instruction:Allows specifying a message history to guide the model's responses, with roles like system, user, and assistant, building a conversation context (e.g., "MESSAGE user Is Toronto in Canada?", "MESSAGE assistant yes").

These Modelfile options provide granular control over model behavior, making it possible to tailor responses for specific use cases, such as creative writing, technical support, or data analysis.Environment VariablesOllama's server behavior can be configured through environment variables, offering flexibility for system and network settings:OLLAMA_HOST: Changes the bind address, defaulting to 127.0.0.1:11434, allowing configuration for network accessibility.
OLLAMA_MODELS: Sets the directory for model storage, defaulting to ~/.ollama/models on macOS, /usr/share/ollama/.ollama/models on Linux, and C:\Users\%username%\.ollama\models on Windows.
OLLAMA_KEEP_ALIVE: Controls how long models stay in memory, defaulting to 5 minutes, with options for duration strings (e.g., "10m"), seconds (e.g., 3600), negative values for infinite retention, or 0 for immediate unload.
OLLAMA_MAX_QUEUE: Sets the maximum number of queued requests before returning a 503 error, defaulting to 512.
OLLAMA_MAX_LOADED_MODELS: Determines the maximum concurrent models loaded, based on memory and GPUs, defaulting to 3 times the number of GPUs or 3 for CPU-only systems.
OLLAMA_NUM_PARALLEL: Sets the maximum parallel requests per model, auto-selecting 4 or 1 based on memory availability.
OLLAMA_FLASH_ATTENTION: Enables Flash Attention to reduce memory usage, set to 1 for activation.
OLLAMA_KV_CACHE_TYPE: Sets the quantization type for the K/V cache, affecting memory usage and precision, with options like f16 (default), q8_0 (1/2 memory, small precision loss), and q4_0 (1/4 memory, medium precision loss).
OLLAMA_CONTEXT_LENGTH: Overrides the default context window size of 4096 tokens, allowing settings like 8192 for larger contexts.
HTTPS_PROXY: Redirects outbound model pulls through a proxy, requiring a system-installed proxy certificate.
OLLAMA_ORIGINS: Configures additional web origins for cross-origin requests, defaulting to 127.0.0.1, 0.0.0.0, with examples like chrome-extension://*,moz-extension://*,safari-web-extension://*.

These variables allow users to optimize server performance, manage resources, and ensure compatibility with various network environments, especially important for server deployments.Automated Features for GPU and System AssessmentOllama includes several automated features that assess system capabilities and optimize performance, particularly for GPU utilization and memory management:GPU Detection and Utilization: Ollama automatically scans for available GPUs upon launch, assessing compatibility and available VRAM. It supports NVIDIA GPUs with compute capability 5.0 or higher and AMD graphics cards in preview on Windows and Linux as of recent updates. This automatic detection ensures efficient use of GPU acceleration, potentially speeding up inference by up to 2x compared to CPU-only setups.
Memory Management: Parameters like OLLAMA_MAX_LOADED_MODELS and OLLAMA_NUM_PARALLEL are auto-configured based on system memory and GPU count. For instance, OLLAMA_MAX_LOADED_MODELS defaults to 3 times the number of GPUs or 3 for CPU systems, ensuring optimal resource allocation without manual intervention.
Context and Token Settings: While context size (CTX) and max token settings (via num_ctx and num_predict in the Modelfile or OLLAMA_CONTEXT_LENGTH) are primarily manual, Ollama provides defaults (e.g., 2048 tokens for context) that are generally suitable for most systems. The auto-selection of parallel requests based on memory indirectly influences these settings by managing system load.
Model Layer Automation: Research suggests that model layers can be influenced through the ADAPTER instruction for applying LoRA adapters and OLLAMA_KV_CACHE_TYPE for quantization, which affects how the model is loaded into memory. However, exact automation for model layers is less clear, and users may need to manually configure these for optimal performance based on hardware.

These automated features reduce the need for manual configuration, making Ollama accessible for users with varying levels of technical expertise, while still offering advanced customization for power users.Specific Settings for Context (CTX), Max Tokens, and Model LayersContext (CTX) Settings: The context window size can be set via num_ctx in the Modelfile, defaulting to 2048, or overridden with OLLAMA_CONTEXT_LENGTH as an environment variable. This controls how much previous conversation the model considers, crucial for maintaining coherence in long interactions.
Max Token Settings: The num_predict parameter in the Modelfile specifies the maximum tokens to predict, defaulting to -1 for infinite, but can be set to a specific number like 42 for limiting output length. This is essential for managing response length and system resources.
Model Layers: Model layers can be influenced through the ADAPTER instruction, which applies fine-tuned LoRA adapters, and OLLAMA_KV_CACHE_TYPE, which sets quantization levels (e.g., q4_0 for 1/4 memory usage). These settings effectively adjust the model's precision and memory footprint, potentially impacting layer-wise performance, though automation is limited to system detection rather than dynamic layer adjustment.

Additional Features and IntegrationsBeyond the core adjustable options, Ollama offers additional features that enhance its utility:Tool Support: As of recent updates, Ollama supports tool calling with models like Llama 3.1, enabling models to use external tools to perform complex tasks or interact with the outside world, expanding its applicability for advanced workflows.
Integration with Other Platforms: Ollama integrates seamlessly with platforms like LangChain, n8n, and Jupyter notebooks, facilitating use in data science environments. For instance, Jupyter AI extensions allow running Ollama models locally within notebooks, enhancing interactive development.
